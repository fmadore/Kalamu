# 2026-10-30 · Version 1.0.0: the rest of the refactor, and the Store package

## Context

The [29 October checkpoint](2026-10-29-checkpoint.md) left two pieces of its refactor after the
integrity and cost fixes and the reviews' frame: oversized components and engine files, and the
rules on which files and models suit a task, kept in two places. Search in the review had
reached the text and table of contents reviews but not the analysis review. Version 1.0.0, the
first Microsoft Store submission, also needed what the Store checks: a way to report AI output,
a package with FFmpeg inside, the licences of everything built in, and files reviewers can use.
This is also the end of a milestone, the first release, so the architecture was reviewed again
against AGENTS.md (below).

## Decisions

- **Search in the analysis review** keeps the fields whose answers or reasons, from any set-up,
  hold the words, marked where they stand; in a text document the words are also marked in the
  document and counted. The words pointed at in the answers and the words searched for are now
  found by the same matching (`findTerm` uses the search's), so "segou" finds "Ségou" in both.
- **The engine's job loop in three files**: `plan.rs` (the pieces a source is cut into, and
  each piece × set-up recorded before anything is sent), `piece.rs` (one piece's call, and the
  saving of a piece's state and of a cost, which batches used to repeat) and `run.rs` (the
  loop); `batch/send.rs` and `batch/collect.rs` beside the batch types. Behaviour is unchanged:
  the engine's tests pass as they were.
- **Which files, models and formats suit a task is the engine's to say.** `Task` gives the kinds
  of source it reads, the formats it writes and whether the job's language is the answers';
  the engine's `task_rules` adds the models of the catalogue in use that do it (and, for a table
  of contents, those that combine pages) and the app hands them to New job through a command,
  fetched again when the catalogue is refreshed. `create_job` checks them: a source the task
  does not read, or a model the catalogue lists that does not do the task or cannot read a
  YouTube link, is refused; formats the task does not write are left out. A model the catalogue
  does not list is left to its provider, as before. `cargo test` writes the bundled catalogue's
  rules to `src/lib/dev/taskRules.json`, for the front end's tests and the sample data, as it
  writes the TypeScript bindings.
- **New job, the job page and the sidebar** are split into components, with no change in what
  they show.
- **Icons**: the icon component styled every `.icon` as a block, and icon-only buttons are
  `.btn.icon`, so whenever its style loaded after the global one those buttons stopped centring
  their icon. The rule now names the SVG (`svg.icon`). Every interface icon is Lucide, through
  `Icon.svelte`; no emoji or text symbol stands in for one.
- **Report a problem** (Store policy 11.16) opens the GitHub issue form for AI output
  (`.github/ISSUE_TEMPLATE/output.yml`) in the browser, with the version filled in: a flag in
  every review's masthead, a button in Settings › About. Kalamu sends nothing; the form warns
  that the page is public. The privacy policy says so.
- **The MSIX package**, ported from Live Translation (`@choochmeque/tauri-windows-bundle`, a
  committed `src-tauri/gen/windows/`, `resources.pri` for the taskbar icons). Where Kalamu
  differs: no microphone capability; FFmpeg and its licences are laid in from
  `tauri.ffmpeg.conf.json` as a temporary `tauri.windows.conf.json`, which the bundler and
  `tauri build` read, so ordinary builds still need no FFmpeg; the logos are rendered by
  `scripts/msix-assets.py` from the two sources DESIGN.md names; and the build refuses to run
  while the manifest carries `PARTNER-CENTER-PACKAGE-NAME`, since a wrong identity fails only
  at ingestion, after a long build. The release workflow builds both packages and one
  `.msixbundle`, and publishes nothing until all are attached.
- **Third-party notices from `cargo metadata` and `package-lock.json`** rather than
  `cargo about`: nothing to install on the release runners, and the same script runs locally.
  It lists the crates reachable from the app through normal dependencies on the target, and
  the front end's non-development packages (pdf.js's optional Node canvas builds are left out:
  they never reach the bundle), with their licence files, each distinct text printed once, and
  whisper.cpp's licence from inside `whisper-rs-sys`.
- **Sample files** made for Kalamu (CC0): a recording of Windows' speech synthesis, the
  synthetic newspaper page the preview uses, and its text. Real archival material would raise
  rights questions a certification team should not have to weigh.

## Checkpoint: the first release

1. **Specification, roadmap and AGENTS.md** were re-read against the code. The specification
   gains *What each task accepts*, Report a problem and the analysis search; the roadmap's
   *Next* keeps the two checkpoint items that change no result (the cost of failed answers,
   smaller provenance gaps).
2. **Dependencies still point inwards.** `core` gained only data about tasks (no I/O); the
   engine's new module uses the catalogue through its existing queries; the app adds one
   command. Each crate keeps one job.
3. **Duplication**: the piece-saving and cost code shared by single calls and batches is now
   one; the front end's copy of the task rules is gone. Accepted as before: provider
   constructors and batch cancellation repeating a few lines.
4. **Resuming, caching, progress and provenance** cover every path as at the last checkpoint:
   the split moved code without changing what is recorded before and after each call.
5. **Files over 500 lines**: `PipelineDiagram.svelte` (one drawing, as decided), `ReviewView`
   (782), `en.ts`, the sample data and tests, `catalog` (651, its cost estimates still to move
   to a module of their own), `store` (one file, as decided), `prompts`' defaults (data). None
   blocks the release.

## Consequences

- What is left before submitting is outside the code: the package name from Partner Center,
  GitHub Pages for the privacy policy, the v1.0.0 tag, live runs and screenshots from the
  installed package, and the decision on a test key ([microsoft-store.md](../microsoft-store.md)).
- Adding a task now means its `Task` rules in `core`; New job and the engine follow.
- A change to the catalogue or the rules is followed by `cargo test`, which refreshes
  `taskRules.json`.
