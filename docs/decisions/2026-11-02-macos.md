# 2026-11-02 · Kalamu on macOS

## Context

Colleagues on Macs asked for Kalamu. The app was written for Windows only, by a maintainer
without a Mac, so a port has to be built and checked in GitHub Actions. A first CI lane on
`macos-latest` showed that the workspace already compiled and passed every test there: the
domain crates were portable, as AGENTS.md requires. What was Windows-shaped sat in the shell
and the interface: JSON opened in Notepad, the window and tray followed Windows conventions,
the review's player assumed Chromium's codecs, shortcuts read Ctrl only, and the copy said
"this PC" and "Windows Credential Manager". FFmpeg was built for Windows only, and packaging
knew only NSIS and MSIX.

None of the three reference projects runs on macOS: Live Translation, which gave Kalamu its
plumbing, ships for Windows only. So nothing here is ported; it follows Tauri's own macOS
conventions.

## Decisions

- **Apple Silicon only, unsigned for now.** A `.dmg` signed ad hoc (Apple Silicon runs nothing
  unsigned at all) is attached to each GitHub release. Gatekeeper asks once, on first opening,
  and the Keychain may ask again after an update. Signing and notarisation with an Apple
  Developer ID come later; `release.yml` names the secrets they need (done after 1.3.0:
  [signing and notarisation](2026-11-04-macos-notarisation.md)). No Intel build (Apple
  stopped selling Intel Macs in 2023) and no Mac App Store (its sandbox and running FFmpeg as a
  separate program do not mix).
- **One place per layer for what differs between systems.**
  - The shell: `src-tauri/src/platform/`, one file per system with the same items: the app that
    opens JSON (Notepad, TextEdit), whether the red button hides the window, where the tray menu
    opens, the player's profile, the Scriptorium data-folder move (Windows only), the macOS
    application menu, the Dock's Reopen event. Any other system is a compile error naming the
    file to add.
  - The crates below the shell receive what they need as values and never match on the system:
    the engine gets the player's profile through `EngineConfig`. `cfg` remains only where the C
    runtime or the operating system itself differs (`ffmpeg.rs` starting a program without a
    console window and its `.exe`, the VAD model's non-ASCII path on Windows).
  - The interface: `src/lib/platform.ts` gives the shortcut modifier (⌘ on a Mac), writes
    shortcuts as each system does, and picks the names of the keychain and the tray from the
    translation files. Components never test the system.
  - Tauri's own configuration: `src-tauri/tauri.macos.conf.json`, merged by Tauri on macOS
    only (targets, the `.icns` icon, macOS 13 and later, ad-hoc signing).
- **The player's formats are a profile, not an assumption.** `kalamu_media::Playback` lists what
  the review's player plays as is and what a converted copy is written in: `CHROMIUM` (today's
  lists) and `WEBKIT`, where Ogg and WebM recordings are converted to FLAC, which WebKit has long
  played, rather than to Ogg Opus, which only its latest releases play.
- **Mac conventions where the systems differ.** The red button hides the window and the app
  stays in the Dock; the Dock icon brings it back. Quit (⌘Q) in the application menu goes
  through Kalamu's own item, because the system's ends the process at once: while jobs run it
  asks first, as closing the window does on Windows. Tauri's default menu is kept otherwise,
  since it gives the Edit shortcuts (⌘C, ⌘V…). The tray menu opens on a click in the menu bar.
- **Portable fixes rather than per-system ones.** Folders skip the `._name` files macOS leaves
  on shared drives (they reach Windows too); generated names are capped in UTF-8 bytes as well
  as characters, for APFS's 255-byte limit.
- **FFmpeg for macOS** is the same audio-only LGPL configuration, built natively with Apple's
  clang for macOS 13 and later, linking only what macOS itself provides, and published in the
  same `ffmpeg-<version>-<n>` release as the Windows builds.
- **WebKit in CI.** The maintainer cannot open the app on a Mac, so a `webkit` job runs the
  interface's sample data (`?mock`) in Playwright's WebKit on `macos-latest`: every main screen
  opens without an error, shortcuts show ⌘, and the player accepts each format the engine gives
  it. The macOS Rust lane is required like the Windows ones.

## Consequences

- A release also builds `Kalamu_<version>_aarch64.dmg`, and is published only once it is
  attached.
- What CI cannot check needs a Mac user before a release is announced for macOS: Gatekeeper's
  first opening, the Keychain's prompts on an unsigned build, ⌘Q, the Dock and the red button
  in the real webview, the menu-bar icon, and YouTube's player in WKWebView.
- The macOS application menu's labels are English until they go through the translation files.
- The specification, roadmap, README, privacy policy, security policy and development notes now
  name both systems; the Store listing stays Windows-only.
