# 2026-11-09 · A review of the whole app, and what it fixed

## Context

The [8 November checkpoint](2026-11-08-checkpoint.md) looked at structure: what is duplicated,
which files have grown, whether dependencies still point inwards. This review looked for what a
researcher would meet: bugs, work or money lost, screens that break, and what would make the app
better to use. Three read-only reviews ran in parallel (the crates below the offline engines;
the offline engines, media, the shell and CI; the interface's code), and every screen was opened
on its sample data (`?mock`) in light and dark, English and French, at 1440 × 900, 1000 × 700 and
700 × 900. The roadmap and the open issues were read against the code. The findings acted on
were checked against the code first; those only recorded are marked where they rest on a
reading that was not reproduced.

The Rust crates were tested where the review ran (Linux): `core`, `providers`, `engine`, `store`
and `search`. `offline` and the shell do not build there, so CI is the first to compile them
with these changes.

## Decisions

- **macOS 14 is the minimum**, 13 before (`tauri.macos.conf.json`, README, specification, store
  listing). The interface uses the popover API, which WebKit has from Safari 17. The correction
  editor relied on `field-sizing: content`, which WebKit has only from Safari 26.2: rather than
  ask for macOS 26, the editor grows with its text in script where the rule is missing
  (`caret.ts` `growWithText`). FFmpeg's and llama.cpp's programs stay built for macOS 13 and
  later, which runs on 14.
- **An answer cut off at the output limit is not asked for again.** The same request meets the
  same limit; four attempts were four bills. `ProviderError::CutOff` is neither retryable nor
  fatal for the job, carries its usage, and is counted with the refused answers in provenance.
  A cut-off answer that still reads as whole JSON is kept.
- **A batch is given up on** when the provider says for good that it cannot be read (it was
  deleted, the key is another organisation's), and when it is still unreachable a day past its
  window after thirty failed polls in a row in one session; one failure on a computer just woken
  loses nothing. A day, because Gemini allows up to 48 hours.
- **A wait a provider asks for is at most five minutes**, in the header as in the message, and
  a value that is no number of seconds is ignored.
- **Any early stop with text is "cut off"**, not only the output limit: Gemini's other finish
  reasons and OpenAI's other `incomplete` reasons were stored as whole pages.
- **A format that cannot be written is said**, on the job as a source's failure, the other
  formats written all the same. A correction or speakers' names are kept whatever happens to
  the files, so saving them does not fail for a file. ALTO and the searchable PDF are skipped
  quietly for a set-up whose model places no text, which a comparison of two models makes
  ordinary.
- **Leaving a changed draft asks first**, the same way everywhere: one guard in
  `state.svelte.ts` (`guardDraft`, `leaveThen`) that `go()` and the reviews' own page turning
  consult, for a correction, an analysis's or a table of contents' edit, a prompt and a
  workflow. Only a text that differs from what was opened asks.
- **New job's form is kept** when the researcher leaves it (for a key or language data in
  Settings) and comes back with nothing new to start from; an opening with a task, files or a
  project starts afresh, and *Start over* empties it.
- **While a dialog is open the rest of the window is inert** and the window's shortcuts are
  held; the close question answers Escape as *Stay*.

## Done

**Engine, providers, store**

- The six decisions above, each with a test: recorded responses for the cut-off analysis
  (`anthropic_max_tokens_analysis.json`), Gemini's early stop and OpenAI's `incomplete`; engine
  tests for one attempt and its cost, both ways a batch is given up on, a pause during the wait
  before a batch is sent, a recording planned in part, and a format that cannot be written.
- **A recording's plan is recorded whole**: `JobStore::upsert_pieces` writes a source's pieces in
  one transaction, and stored cuts are used again only when they run without a gap to the end of
  the recording. Before, a crash while the first set-up's pieces were written left a plan of the
  first few segments, which a resumed job transcribed and called complete.
- The wait before a batch is sent ends on pause or cancel (`wait_unless_stopped`).
- The three providers that repeated it read analysis-like answers through one `analysis::read`.
- The engine hands out its catalogue as an `Arc` instead of a copy several times a piece.
- Indexes for the lookups by job and by document that deleting a job or a document makes
  (`document_links`, `preferred_results`, `collection_documents`).

**Interface**

- The review in a short window: once the panes stack (1000 px and narrower) the text pane could
  shrink to nothing and lie over the page strip (seen at 1000 × 700; the window may be 640 × 560).
  The source gives way first, the text keeps 16rem, and the work area scrolls when that does not
  fit. At 760 px and narrower the sidebar is folded to one row, as DESIGN.md said and the build
  did not.
- Answers that arrive late no longer replace newer ones: the cost estimate beside Start, a
  task's prompts, a dictionary row's evidence, the list of what to check, a project search.
- A document's description being written survives a tag, a collection or a preferred result
  changed on the same page.
- Folders dropped on a project are opened like those added with the button.
- A project opens on its documents again; it comes back to Search once, after a match was opened
  from it.
- Failures that were never shown now are: *Show in folder* on a file that has moved, a download
  that cannot be cancelled, prompts that cannot be loaded, a quit that fails. A message shown
  twice stays four seconds from the second time. *Add to project* in a job's menu updates the
  sidebar's count.
- The job page's *Errors found in review* has a row of its own under the short facts, where it
  wrapped into a narrow column several times their height.
- A source description's fields are the same height with or without *From the project*.
- Keyboard focus in the menus keeps the ink outline, where it took the hover's wash.

## Left, and where it is tracked

- [#143](https://github.com/fmadore/Kalamu/issues/143) Large jobs: exports quadratic in a job's
  size, every project's links read for each export, every output written again for each
  correction, the job list reading through results' payloads, tables and thumbnails, batches of
  150 MB held several times over, a cache never pruned. None measured yet.
- [#144](https://github.com/fmadore/Kalamu/issues/144) Offline engines and media: FFmpeg can be
  neither cancelled nor timed out, llama.cpp has no watchdog, one failure gives the graphics
  processor up for the session, downloads start again from nothing, 1-bit TIFF and 24-bit AIFF.
- [#145](https://github.com/fmadore/Kalamu/issues/145) The release pipeline: signing secrets in
  the environment of build code, the Windows app never linked on a pull request, the screens
  opened only in WebKit, no interaction tests, no checksums.
- [#146](https://github.com/fmadore/Kalamu/issues/146) Keyboard and accessibility.
- [#147](https://github.com/fmadore/Kalamu/issues/147) A model's abilities in the catalogue, not
  matched on its name: an architecture checkpoint item.
- [#148](https://github.com/fmadore/Kalamu/issues/148) The shell: a start-up failure with no
  message, an update notice, the tray computed in the webview.
- [#149](https://github.com/fmadore/Kalamu/issues/149) Interface: a history to go back through,
  remembered views, a shortcut overview and smaller improvements.
- Not in an issue: CSV cells that begin with `=`, `+`, `-` or `@` are read as formulas by a
  spreadsheet (in the roadmap's first item).

[#122](https://github.com/fmadore/Kalamu/issues/122) (the graphics processor for the offline OCR
models on Windows) is closed: what it asked for shipped in 1.5.0, and the timings still to take
are among the roadmap's live runs.

## To check

  on the three CI lanes.
- The interface's fixes on Windows and in WebKit: they were tried in Chromium on the sample
  data. The editor growing in script was tried with `field-sizing` switched off, not in an older
  WebKit.
- An analysis stopped early by a provider's filter with half an answer now gets the output-limit
  message, where it was asked again: rare, and the wording is off for it.
- In a very short window, following a recording or a table of contents can scroll the work area
  as well as its pane.
