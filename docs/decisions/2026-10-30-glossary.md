# 2026-10-30 · A glossary

## Context

Kalamu is for researchers who are not technical, and many colleagues meet OCR, LLMs and error
rates for the first time in it. The interface used words it never explained (pipeline, tokens,
provenance, economy mode), and the export formats were offered by name alone. The roadmap asked
for a glossary beside Settings, linked from where the words appear.

## Decisions

- **A page of its own, beside Settings in the sidebar**, rather than tooltips: a definition
  worth reading is a few sentences, and a page can be read through by someone preparing a
  project, filtered, and linked within itself. Fifteen words: those the roadmap listed (OCR and
  HTR, LLM, prompt, pipeline, tokens, reasoning effort, ground truth, character and word error
  rates, hallucination, provenance, machine-readable) and four the app relies on (Whisper, API
  key, set-up and comparison, economy mode). Then every export format with what it suits, and
  `provenance.json`.
- **Ordered as a reader would learn them**, not alphabetically: what a model is, then how it is
  used, then how its results are checked and recorded. A filter finds a word, forgiving
  capitals and accents as the review's search does. Each entry names the words it leans on
  ("See also").
- **Set as a reader's glossary**: the word in bold beside its definition in the reading face,
  stacked on a narrow window. A word gone to from elsewhere is marked with the highlighter's
  edge, as a table of contents marks the page shown.
- **A small help mark beside the headings that use a word**: pipelines, the model and prompt,
  speed and price (economy mode), the estimate (tokens), formats, the files written
  (provenance) and the errors found in review (error rates). It is smaller than an icon button,
  so the headings keep their height, and is named for screen readers by the question it
  answers ("What is meant by Tokens").
- **The definitions are interface text**, in `en.ts` like every visible string, so French and
  German translate them with the rest; `glossary.ts` only orders and links them. Its list of
  formats is keyed by the `ExportFormat` type generated from Rust, so a new format fails the
  type check until it is placed and described; its tests check that every word is listed once
  and every cross-reference exists.

## Consequences

- A new word the interface relies on gets its entry; a new export format cannot be forgotten,
  as the type check fails until it has one.
- The definitions describe the app as it is (reasoning effort is set per task, Whisper cannot
  label speakers, economy mode answers within a day): they change when the app does.
